# MiniMax H3 ComfyUI 工作流

## 当前阶段

`minimax_h3_prototype.workflow.json` 是跨电脑传输用的流程原型，不调用网络，也不执行本地推理。它用于确认：

- 写实、国漫、电影级 3D 三种风格分支；
- 长打斗按自然动作阶段拆分；
- 上一段尾帧与状态表接续下一段；
- 生成后质量门禁；
- MP4 母版与 GIF 预览双输出；
- 招式 35 的固定动作门禁。

原型中的 MiniMax、拼接和 GIF 节点均为说明性占位节点。测试通过后，才替换为真实 H3 API、自定义节点或已安装插件节点，并另存为正式模板。

## 在另一台电脑测试

1. 克隆或复制整个仓库，不要只复制 workflow JSON。
2. 启动 ComfyUI。
3. 将 `workflows/minimax_h3_prototype.workflow.json` 拖入 ComfyUI 页面。
4. 检查三种风格分支、两段生成链、连续性检查点、质量门禁和两个输出端是否完整显示。
5. 此阶段不要填写 API key，也不会执行 Queue。
6. 截图或记录缺失节点、导入警告和 ComfyUI 版本。

## 后续接入 H3 的安全约定

- API key 只能从环境变量 `MINIMAX_API_KEY` 读取。
- 禁止把 key 写进 workflow JSON、节点默认值、日志、截图或 Git。
- 正式节点需实现：创建任务、轮询状态、超时、失败信息、下载 MP4、可控重试。
- 网络超时和限流可以重试；参数错误、鉴权失败和内容审核失败不能自动无限重试。

## 正式模板验收条件

- 在目标电脑上可无警告导入。
- 三种风格各完成至少一个真实 H3 片段。
- 尾帧接力后角色、服装和武器保持一致。
- 中断后可从未完成片段继续，不必重跑整场。
- MP4 拼接顺序正确，GIF 文件名符合 `<编号>-<名称>.gif`。
- 工作流文件不包含任何凭据。

## 静态校验

在仓库根目录运行：

```bash
python -X utf8 -m unittest discover -s tests -p "test_*.py" -v
```

静态校验只证明 JSON 结构、节点和连线完整，不证明目标电脑上的 ComfyUI 节点兼容或 H3 API 可用。
