# MiniMax H3 ComfyUI 工作流

## 当前阶段

`minimax_h3_prototype.workflow.json` 是跨电脑传输用的流程原型。本机负责根据资料生成分段提示词，用户再把提示词复制到另一台电脑的 ComfyUI；ComfyUI 只负责调用 H3、检查接力、拼接和导出。当前原型不调用网络，也不执行本地推理。它用于确认：

- 写实、国漫、电影级 3D 三种风格分支；
- 长打斗按自然动作阶段拆分；
- 上一段尾帧与状态表接续下一段；
- 生成后质量门禁；
- MP4 母版与 GIF 预览双输出；
- 招式 35 的固定动作门禁。

原型中的提示词输入、MiniMax、拼接和 GIF 节点均为说明性占位节点。提示词不会在 ComfyUI 内自动生成；每个分段提示词由本机编写并人工粘贴。测试通过后，才替换为目标电脑已有的 H3、视频拼接和 GIF 节点，并另存为正式模板。

## 在另一台电脑测试

1. 克隆或复制整个仓库，不要只复制 workflow JSON。
2. 启动 ComfyUI。
3. 将 `workflows/minimax_h3_prototype.workflow.json` 拖入 ComfyUI 页面。
4. 检查三种风格说明、分段提示词粘贴入口、两段生成链、连续性检查点、质量门禁和两个输出端是否完整显示。
5. 将本机生成的“片段 A 提示词”和“片段 B 提示词”分别粘贴到对应入口；不要把整场提示词重复粘进每个片段。
6. 此阶段不要填写 API key，也不会执行 Queue。
7. 截图或记录缺失节点、导入警告和 ComfyUI 版本。

## 本机提示词交接格式

每个片段单独复制，格式固定为：

```text
招式编号与名称：
风格：写实 / 国漫 / 电影级 3D
片段：A / B / C...
片段职责：
起始状态：角色姿态、朝向、距离、武器状态、战损、环境状态
生成提示词：
结束状态：角色姿态、朝向、距离、武器状态、运动趋势、未消散效果
负面约束：
```

片段 B 之后必须把上一段的结束状态原样写入起始状态，并在有条件时同时上传上一段尾帧。最终视频时长不设统一上限，但单次生成仍按一段连续动作拆分。

## 后续接入 H3 的安全约定

- API key 只能从环境变量 `MINIMAX_API_KEY` 读取。
- 禁止把 key 写进 workflow JSON、节点默认值、日志、截图或 Git。
- 正式节点需实现：创建任务、轮询状态、超时、失败信息、下载 MP4、可控重试。
- 网络超时和限流可以重试；参数错误、鉴权失败和内容审核失败不能自动无限重试。

## 正式模板验收条件

- 在目标电脑上可无警告导入。
- 三种风格各完成至少一个真实 H3 片段。
- 尾帧接力后角色、服装和武器保持一致。
- 中断后可从未完成片段继续，不必重跑整场。
- MP4 拼接顺序正确，GIF 文件名符合 `<编号>-<名称>.gif`。
- 工作流文件不包含任何凭据。

## 静态校验

在仓库根目录运行：

```bash
python -X utf8 -m unittest discover -s tests -p "test_*.py" -v
```

静态校验只证明 JSON 结构、节点和连线完整，不证明目标电脑上的 ComfyUI 节点兼容或 H3 API 可用。
